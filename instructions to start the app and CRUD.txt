DATABASE SAFETY:

Use the application/API for normal create, read, update, and delete operations.
The SQL statements in this file are read-only inspection queries. Do not run
unqualified DELETE or UPDATE statements against users or business tables.
Run write tests only against a disposable database with no important data.
The CRUD load-balancing verifier creates and deletes temporary job records.

CRUD OPERATIONS AND DATABASE INSPECTION:

List application tables:
SELECT table_schema, table_name
FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_type = 'BASE TABLE'
ORDER BY table_name;


Check the allowed account roles:
SELECT conname AS constraint_name,
       pg_get_constraintdef(oid) AS constraint_definition
FROM pg_constraint
WHERE conrelid = 'public.users'::regclass
  AND contype = 'c'
ORDER BY conname;



List accounts without exposing password data:
SELECT id,
       name,
       role,
       requested_role,
       verified,
       active,
       created_at
FROM public.users
ORDER BY id;


view jobs:
SELECT id,
       payload::jsonb ->> 'title' AS title,
       payload::jsonb ->> 'location' AS location,
       payload::jsonb ->> 'type' AS job_type,
       payload::jsonb ->> 'published' AS published,
       payload::jsonb ->> 'recruiterEmail' AS recruiter
FROM public.job_service_documents
WHERE collection_name = 'jobs'
ORDER BY id;


view applications and their status:
SELECT id,
       payload::jsonb ->> 'candidateId' AS candidate_id,
       payload::jsonb ->> 'candidateName' AS candidate_name,
       payload::jsonb ->> 'jobId' AS job_id,
       payload::jsonb ->> 'jobTitle' AS job_title,
       payload::jsonb ->> 'status' AS application_status,
       payload::jsonb ->> 'appliedDate' AS applied_date
FROM public.application_service_documents
WHERE collection_name = 'applications'
ORDER BY id;



See shortlisted, interviewing, and selected applicants:
SELECT id,
       payload::jsonb ->> 'candidateId' AS candidate_id,
       payload::jsonb ->> 'candidateName' AS candidate_name,
       payload::jsonb ->> 'jobTitle' AS job_title,
       payload::jsonb ->> 'status' AS application_status
FROM public.application_service_documents
WHERE collection_name = 'applications'
  AND payload::jsonb ->> 'status'
      IN ('shortlisted', 'interview', 'selected')
ORDER BY id;


Count applications by stage:
SELECT payload::jsonb ->> 'status' AS application_status,
       COUNT(*) AS application_count
FROM public.application_service_documents
WHERE collection_name = 'applications'
GROUP BY payload::jsonb ->> 'status'
ORDER BY application_status;

Find applications for one candidate:
SELECT id,
       payload::jsonb ->> 'candidateId' AS candidate_id,
       payload::jsonb ->> 'candidateName' AS candidate_name,

       payload::jsonb ->> 'appliedDate' AS applied_date

View recent audit events from all three services:
SELECT occurred_at,
       service_name,
       actor_id,
       actor_role,
       operation,
       resource_type,
       resource_id,
       outcome,
       http_status,
       correlation_id
FROM (
    SELECT occurred_at, service_name, actor_id, actor_role, operation,
           resource_type, resource_id, outcome, http_status, correlation_id
    FROM public.auth_service_audit_events

    UNION ALL

    SELECT occurred_at, service_name, actor_id, actor_role, operation,
           resource_type, resource_id, outcome, http_status, correlation_id
    FROM public.job_service_audit_events

    UNION ALL

    SELECT occurred_at, service_name, actor_id, actor_role, operation,
           resource_type, resource_id, outcome, http_status, correlation_id
    FROM public.application_service_audit_events
) AS audit_events
ORDER BY occurred_at DESC
LIMIT 100;



To show only write events, add this condition to the outer query, before ORDER BY:
WHERE operation IN ('CREATE', 'UPDATE', 'DELETE')


SAFE STOP AND START THE PROJECT

TO STOP:

Stop the frontend in VS Code: find the terminal running Vite and press Ctrl+C

Stop the microservices:

$expectedJars = @(
    'eureka-server-1.0.0.jar',
    'auth-service-1.0.0.jar',
    'job-service-1.0.0.jar',
    'application-service-1.0.0.jar',
    'gateway-1.0.0.jar'
)

$stoppedProcessIds = [System.Collections.Generic.HashSet[int]]::new()

Get-CimInstance Win32_Process -Filter "Name = 'java.exe'" |
    ForEach-Object {
        $processInfo = $_
        $jarMatch = [regex]::Match(
            [string]$processInfo.CommandLine,
            '(?i)-jar\s+"?([^"\s]+)'
        )

        if ($jarMatch.Success) {
            $jarName = [System.IO.Path]::GetFileName($jarMatch.Groups[1].Value)

            if ($expectedJars -contains $jarName) {
                $processIdValue = [int]$processInfo.ProcessId
                if ($stoppedProcessIds.Add($processIdValue)) {
                    Stop-Process -Id $processIdValue
                    Write-Host "Stopped $jarName (PID $processIdValue)."
                }
            }
        }
    }


Check that the standard TalentSync ports are free:

Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.LocalPort -in 8761,8080,8081,8083,8084 } |
    Select-Object LocalPort, OwningProcess

POSTMAN ROUTES FOR JOB CRUD:

Use the gateway URL http://localhost:8080 and a verified recruiter JWT:
- GET /api/jobs and GET /api/jobs/{id}: browse/read jobs
- POST /api/jobs: create a job
- PUT /api/jobs/{id}: update a job
- PATCH /api/jobs/{id}/published: publish/unpublish a job
- DELETE /api/jobs/{id}: delete a test job

In Postman, choose Authorization > Bearer Token and use the token returned by
the verified recruiter's login request. Use the candidate's own token for
candidate actions; do not use a recruiter token to submit an application.
For application workflow, use a candidate JWT to submit with
POST /api/jobs/{id}/apply. Use a recruiter JWT to review GET
/api/admin/applications and update an application with
PATCH /api/applications/{id}/status. Never include a real JWT in screenshots,
committed files, or shared logs.

TWO-INSTANCE JOB CRUD AND LOAD-BALANCING CHECK:

This optional verifier writes temporary records and requires a disposable
database, a verified recruiter token, and two UP job-service instances in
Eureka. It exercises create, read, update, publish/unpublish, delete,
read-after-write, and application-service mirroring across both instances.

1. Stop the ordinary stack if it is already running. In the PowerShell window
   that will launch it, enable the local-only instance response header before
   starting the stack:

$env:LOAD_BALANCING_INSTANCE_HEADER_ENABLED = 'true'
Set-Location 'C:\Users\mekas\Downloads\soa-review\soa-review\microservices'
.\start-microservices.ps1

2. In that same PowerShell window, start a second job-service instance on port
   8085. First confirm that port 8085 is free:

Get-NetTCPConnection -State Listen -LocalPort 8085 -ErrorAction SilentlyContinue

If that command returns a listener, do not stop it unless you have confirmed it
belongs to your own test run. Do not start the second instance on an occupied
port.

$java = Join-Path $env:JAVA_HOME 'bin\java.exe'
$jobInstance2 = Start-Process -PassThru -FilePath $java -WorkingDirectory $PWD `
    -ArgumentList '-jar', (Join-Path $PWD 'job-service\target\job-service-1.0.0.jar'), '--server.port=8085'

Wait until Eureka at http://localhost:8761 shows two JOB-SERVICE instances UP.
The local response header is for verification only; do not enable it in
production.

3. Sign in as a verified recruiter. Enter the JWT using the masked prompt below
   (it is held only in this PowerShell process environment; do not print or
   share it):

$secureToken = Read-Host 'Paste verified recruiter JWT' -AsSecureString
$tokenPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureToken)
try {
    $env:TALENTSYNC_TEST_RECRUITER_TOKEN =
        [Runtime.InteropServices.Marshal]::PtrToStringBSTR($tokenPointer)
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($tokenPointer)
    $secureToken.Dispose()
}

4. Run the verifier with explicit acknowledgement that it writes test data:

.\verify-crud-load-balancing.ps1 -AllowLocalTestWrites `
    -ExpectedInstanceCount 2 -JobCount 10

Require a PASS result and confirm the output reports both job-service
instances for each CRUD method. The script attempts cleanup if a test fails;
inspect the disposable database if it reports cleanup warnings.

5. Remove the token from the environment and stop only the second instance
   started above:

Remove-Item Env:TALENTSYNC_TEST_RECRUITER_TOKEN
Stop-Process -Id $jobInstance2.Id

This verifier covers job CRUD and job-service distribution; it does not by
itself prove every application, interview, authentication, or PostgreSQL
failure/recovery workflow. The regular Java tests use H2 unless the opt-in
PostgreSQL integration tests are explicitly configured for a dedicated
_test/_integration database.
